Para pensar

Hay 4 copias de la tarjeta… no, 40. Mercadeo quiere agregar un ícono. ¿Cuánto cuesta ese cambio hoy y cuánto costará cuando sean 400 eventos?

Ver respuesta

el costo crece con cada copia, y cada copia es un lugar más para equivocarse. Hace falta una pieza única, un componente, que se define una vez y se usa para todos los eventos. Se cambia en un lugar y cambia en todas partes.

Para pensar

El evento se agotó a las 3 p. m. y el botón siguió activo. ¿El problema fue de Julián o del diseño de la página?

Ver respuesta

del diseño. La página guarda el dato (cupos) y la vista (el botón) por separado, y alguien tiene que sincronizarlos a mano. Lo que falta es que la vista se calcule a partir del dato: si los cupos son 0, el botón se bloquea solo. Eso es data binding.

3.1 · ¿Por qué Angular?

El problema de fondo

El correo de Valentina no es raro: casi todas las empresas empiezan con HTML y JavaScript sueltos. Funciona mientras la página es pequeña. Cuando crece, cada cambio cuesta más y cada copia es un riesgo. Angular existe para que la interfaz crezca sin volverse frágil.

Definición técnica

conjunto de herramientas y reglas que define cómo se estructura una aplicación y que llama a tu código en el momento correcto.

Explicación sencilla: en vez de decidir tú cómo se organiza todo, el framework ya trae la organización y tú llenas las piezas.

En la vida real

una franquicia. El local ya trae cocina, recetas y procesos; tú preparas el plato.

SPA · Single Page Application

Definición técnica

aplicación web que carga un solo documento HTML y luego cambia su contenido con JavaScript, sin recargar la página.

Explicación sencilla: el navegador descarga la app una vez; de ahí en adelante solo cambia lo que se ve.

En la vida real

la pantalla de vuelos del aeropuerto. No cambian la pantalla cada vez que sale un vuelo: cambian los datos que muestra.

¿Por qué un framework "con opinión"?

Para pensar

Si con JavaScript puro se puede hacer todo, ¿por qué una empresa elegiría Angular, que impone su forma de hacer las cosas?

Ver respuesta

porque en un equipo la consistencia vale más que la libertad. Angular trae decididos el router, el cliente HTTP, la inyección de dependencias, las pruebas y la CLI. Un dev nuevo encuentra cualquier proyecto Angular organizado igual y es productivo desde el primer día.

3.2 · Leer TypeScript

Por qué aparece aquí

Angular se escribe en TypeScript. Sin tres ideas básicas de TypeScript, el código de hoy se lee como jeroglífico. No es un curso de TypeScript: es lo mínimo para leer lo que viene.

Definición técnica

lenguaje que extiende JavaScript con tipos; se traduce (compila) a JavaScript antes de llegar al navegador.

Explicación sencilla: es JavaScript con etiquetas que dicen qué clase de dato va en cada lugar, y un revisor que te avisa antes de ejecutar si te equivocaste.

En la vida real

el formulario de un banco con casillas marcadas "solo números" o "fecha". No puedes escribir tu nombre donde va el valor.

Las tres ideas que usaremos hoy

Este fragmento no va en ningún archivo del proyecto: es para proyectar o probar en el TypeScript Playground. Muestra un tipo en una variable, un tipo con opciones cerradas y una interfaz.

Código
let cupos: number = 120;

type Categoria = 'Concierto' | 'Teatro' | 'Stand-up';
let categoria: Categoria = 'Teatro';

interface Evento {
  nombre: string;
  cuposDisponibles: number;
}

Línea a línea

  • L1 · let cupos: number = 120; → Los dos puntos dicen "esta variable solo guarda números". Si después alguien escribe cupos = 'muchos', TypeScript marca el error antes de ejecutar.
  • L3 · type Categoria = ... → Crea un tipo nuevo con tres valores permitidos y ninguno más. La barra | se lee "o".
  • L4 · let categoria: Categoria → Si alguien escribe 'Concieto' (mal escrito), TypeScript lo detecta. En el HTML de Julián, ese error habría llegado al público.
  • L6–9 · interface Evento → Describe la forma que debe tener un evento: qué campos y de qué tipo. No crea ningún evento; es el molde contra el que se revisan.
Para pensar

Si se convierte en JavaScript antes de llegar al navegador, ¿para qué sirven los tipos si al final desaparecen?

Ver respuesta

sirven mientras se escribe: el editor y el compilador detectan errores antes de que lleguen al usuario. Es una revisión automática que ocurre en tu computador, no en el del público.

Explicación sencilla: un asistente que arma el esqueleto del proyecto y cada pieza nueva siempre igual, para que nadie las haga "a su manera".

el molde de una constructora: todas las casas del conjunto salen con los mismos cimientos.

Paso 1 · Crear Tarima

Se ejecuta desde la carpeta donde guardas tus proyectos (por ejemplo Documentos/proyectos). Crea la carpeta tarima-web con todo el proyecto e instala sus dependencias.

Terminal

Cada opción responde por adelantado una pregunta que el CLI haría:

Resultado esperado: una lista de CREATE ... y al final "Packages installed successfully." Tarda de 1 a 3 minutos (descarga librerías).

Por qué antes de los componentes

Una tarjeta, todos los eventos

Misión del bloque
Para Valentina

una sola tarjeta para todos los eventos, que se vea agotada y no deje reservar cuando no hay cupos, y que avise cuando quedan pocos.

Lo que hacemos

TarjetaEvento recibe un evento con input() y calcula todo lo que muestra a partir de sus datos.

Cómo sabemos que quedó

"Risas sin Filtro" (0 cupos) aparece con la etiqueta "Agotado" y el botón Reservar bloqueado, sin que nadie lo haya marcado a mano.

Definición técnica: mecanismo con el que la plantilla declara una relación entre los datos del componente y la vista, y Angular la mantiene sincronizada. Tiene tres formas básicas:

SintaxisDirecciónEjemplo de hoy
{{ expresión }} · interpolaciónDato → texto en pantalla{{ evento().nombre }}
[propiedad]="expresión" · property bindingDato → propiedad de un elemento[disabled]="estaAgotado()"
(evento)="método()" · event bindingPantalla → código(click)="alternarDescripcion()"

Explicación sencilla: en vez de buscar el botón y bloquearlo a mano, escribes "este botón está bloqueado cuando el evento está agotado", y Angular se encarga.

En la vida real: el marcador del estadio conectado al juego. Nadie cambia los números a mano: cambian cuando cambia el partido.

Para pensar

Si un evento pasa a tener 0 cupos en los datos, ¿quién debería bloquear el botón: tú, buscándolo con document.querySelector, o el framework?

Ver respuesta

el framework. Con [disabled]="estaAgotado()" declaras la regla una vez; tu código cambia datos, nunca toca el DOM a mano. Así se evita exactamente el incidente del sábado.

Definición técnica

bloques de la plantilla que deciden qué se pinta: @if muestra contenido según una condición (con @else if y @else); @for repite contenido por cada elemento de una lista y exige track para identificar cada uno.

En la vida real

@if es el letrero "Agotado" que el taquillero cuelga solo si no hay boletas; @for es la fila de asientos: el mismo asiento, repetido por cada puesto.

    const cupos = this.evento().cuposDisponibles;
    return cupos > 0 && cupos <= 10;
  }

  alternarDescripcion(): void {
    this.mostrarDescripcion = !this.mostrarDescripcion;
  }
}

Leer y corregir errores

12.1 · Componentes e inputs

Todos los errores de compilación salen en la terminal de ng serve y en el navegador, en rojo, con un código. El código (NG8001, TS2339…) es lo primero que se lee: dice qué tipo de error es. Después viene el archivo y la línea.

NG8001: 'app-tarjeta-evento' is not a known element

  • Cómo se lee: "Angular no conoce la etiqueta app-tarjeta-evento en esta plantilla".
  • Causa: se usó el componente en una plantilla, pero no se agregó al imports del componente que lo usa.
  • Corrección: en listado-eventos.ts, agregar TarjetaEvento al arreglo imports (y su import arriba).

NG8002: Can't bind to 'evento' since it isn't a known property of 'app-tarjeta-evento'

  • Cómo se lee: "le estás pasando [evento] a algo que no tiene esa entrada".
  • Causa: falta el imports, o la entrada se llama distinto (por ejemplo eventos en vez de evento).
  • Corrección: revisar el imports y que el nombre en [ ] sea exactamente el de input.

NG8008: Required input 'evento' from component TarjetaEvento must be specified

  • Cómo se lee: "la tarjeta exige un evento y no se lo diste".
  • Causa: se escribió <app-tarjeta-evento /> sin [evento]="...". Es input.required haciendo su trabajo.
  • Corrección: pasar el evento: <app-tarjeta-evento [evento]="evento" />.

12.2 · Datos, pipes y control de flujo

TS2339: Property 'nombre' does not exist on type 'InputSignal<Evento>'

  • Cómo se lee: "estás buscando nombre dentro de la caja, no dentro del evento".
  • Causa: se escribió evento.nombre sin paréntesis. Un input() se lee llamándolo.
  • Corrección: evento().nombre.

NG8004: No pipe found with name 'date'

  • Causa: se usó | date en la plantilla sin importar DatePipe en el componente.
  • Corrección: agregar DatePipe al imports de tarjeta-evento.ts (igual con CurrencyPipe y | currency).

NG5002: @for loop must have a "track" expression

  • Causa: se escribió @for (evento of eventos) sin track.
  • Corrección: @for (evento of eventos; track evento.id).

NG0701: Missing locale data for the locale "es-CO" (en la consola del navegador)

  • Causa: se configuró LOCALE_ID con 'es-CO' pero se olvidó registerLocaleData(localeEsCo).
  • Corrección: revisar las líneas 3 y 7 de app.config.ts.

Errores de entorno

  • "The Angular CLI requires a minimum Node.js version…" → actualizar a Node 24 LTS.

  • "Port 4200 is already in use" → hay otro ng serve abierto: cerrarlo con Ctrl+C, o usar ng serve --port 4300.

Comprender

Cómo llega una página a tu pantalla

Cuando escribes una dirección en el navegador pasan cuatro cosas, siempre en este orden.

1

Petición

El navegador envía una petición a la dirección que escribiste.

2 y 3

Respuesta

Un servidor recibe la petición y responde con archivos de texto: HTML, CSS y JavaScript.

4

Página

El navegador lee esos archivos y construye lo que ves.

Navegador

Programa que pide archivos a un servidor, los interpreta y los dibuja en pantalla.

Servidor

Programa que espera peticiones y responde con archivos o datos.

URL

La dirección de lo que se pide: https://tarima-cartelera.co/cartelera.

Frontend y backend

Dos mitades del sistema

Lo que corre en el navegador se llama frontend: es lo que la persona ve y toca. Lo que corre en el servidor se llama backend: guarda los datos y aplica las reglas.

En la vida real

Es como pedir un domicilio. Tú (el navegador) haces el pedido con una dirección (la URL); la cocina (el servidor) prepara y envía los ingredientes (los archivos); y en tu mesa se arma el plato (la página que ves).

Este curso se llama Full Stack porque haces las dos mitades: el frontend con Angular (este módulo) y el backend con Java y Spring Boot (Módulo 2).

Abre cualquier página (por ejemplo, devseniorcode.com) y presiona F12 (en Mac, Cmd + Opción + I). Se abren las DevTools, las herramientas de desarrollo que trae todo navegador.

  • Al hacer clic en una línea, a la derecha aparece su CSS (Styles).
  • En la pestaña Console (Consola) se ejecuta JavaScript.

Haz doble clic sobre cualquier texto en Elements y cámbialo. La página muestra tu texto.

HTML · estructura

Primero, el navegador necesita saber qué es cada dato

Valentina pidió nombre, categoría, fecha, lugar y precio. Antes de pensar en colores, el navegador necesita distinguir el título, los párrafos y el botón.

Definición técnica

HTML

HTML (HyperText Markup Language) es el lenguaje de marcado que describe la estructura de una página. No es un lenguaje de programación: no calcula ni decide; etiqueta el contenido.

Explicación sencilla

Escribes el contenido y lo envuelves en etiquetas que dicen qué es. <h3>Noche de Salsa Brava</h3> le dice al navegador: "esto es un título de tercer nivel".

Etiqueta

El nombre entre < >. Casi siempre va en pareja: <p> abre y </p> cierra.

Elemento

La etiqueta de apertura, su contenido y la de cierre: <p>Teatro del Parque</p>.

Atributo

Información extra dentro de la etiqueta de apertura: en <html lang="es">, lang es el atributo y "es" su valor.

Los elementos se anidan: uno vive dentro de otro, como cajas dentro de cajas. La sangría (los espacios a la izquierda) sirve para ver qué caja está dentro de cuál.

Preparar la carpeta del proyecto

  3. En el panel izquierdo (Explorer), clic en el ícono de New File (archivo nuevo) y escribe index.html.

Sin IA aquí

La primera tarjeta la escribes tú, etiqueta por etiqueta. Si la IA la escribe, no aprendes a leer la estructura que vas a usar toda la noche.

CSS · presentación

Una regla pinta muchas piezas

La cartelera funciona, pero se ve como un documento de 1995. Mercadeo quiere los colores de la marca, tarjetas blancas y que un evento agotado se note de lejos.

Definición técnica

CSS

CSS (Cascading Style Sheets) es el lenguaje que define la presentación de los elementos HTML: colores, tamaños, espacios y posiciones. Se escribe en reglas.

En la vida real

Es la paleta y el manual de acabados de la obra: "todas las puertas, color madera; todos los baños, baldosa blanca". El arquitecto no pinta cada puerta: define la regla una vez.

Anatomía de una reglaCSS
.tarjeta {
  background-color: white;
}
Selector

.tarjeta: a quién se aplica. Un punto delante significa "los elementos que tengan la clase tarjeta".

Declaración

background-color: white;: qué cambia. Tiene una propiedad, dos puntos, un valor y punto y coma.

Clase

Para poder señalar "las tarjetas", primero hay que ponerles nombre en el HTML: eso es una clase.

CSS es una lista de instrucciones del tipo "a todas las tarjetas, ponles fondo blanco".

JavaScript · comportamiento

La información deja de vivir mezclada con el HTML

Cada evento es una copia del HTML y agotar uno exige cambios manuales. Los dos dolores tienen la misma raíz.

i

La idea que lo cambia todo

¿Y si la información de cada evento viviera en un solo lugar, como datos, y el HTML de las tarjetas se calculara a partir de esos datos? Un evento agotado sería solo un número: cuposDisponibles: 0. Y la tarjeta se vería agotada sola.

Para calcular hace falta un lenguaje que haga cálculos. HTML y CSS no pueden: describen, no deciden.

Definición técnica

JavaScript

JavaScript es el lenguaje de programación que ejecuta el navegador. Puede guardar datos, tomar decisiones, reaccionar a lo que hace la persona (clics, teclas) y modificar la página mientras está abierta.

El DOM en la vida real

El DOM es la maqueta de la casa armada con piezas de Lego. El HTML es el plano. JavaScript puede quitar y poner piezas en la maqueta sin tocar el plano.

El DOM

Cuando el navegador lee el HTML, construye en memoria un árbol de objetos: uno por cada etiqueta. Ese árbol se llama DOM (Document Object Model). Lo que ves en pantalla es el DOM dibujado.

JavaScript no edita el archivo index.html: edita el DOM. Por eso, al recargar, la página vuelve a construirse desde el archivo.
